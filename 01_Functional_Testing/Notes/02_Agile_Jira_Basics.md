# Agile & Jira Basics

## What is Agile?

Agile is a software development methodology where software is developed and delivered in small, incremental iterations. It focuses on continuous collaboration, customer feedback, and frequent releases.

**Key Points:**
- Faster software delivery
- Continuous customer feedback
- Team collaboration
- Easy to handle changing requirements

---

## What is Scrum?

Scrum is an Agile framework used to manage software development projects. Work is completed in short iterations called **Sprints**, usually lasting 2–4 weeks.

**Key Features:**
- Sprint Planning
- Daily Scrum Meeting
- Sprint Review
- Sprint Retrospective

---

## Scrum Roles

### Product Owner (PO)
- Defines business requirements.
- Prioritizes the Product Backlog.
- Represents the customer.

### Scrum Master (SM)
- Ensures Scrum practices are followed.
- Removes obstacles for the team.
- Facilitates Scrum meetings.

### Development Team
- Developers
- QA/Testers
- Business Analysts (BA)
- Designers

The team develops, tests, and delivers the product.

---

## What is Jira?

Jira is a project management and issue-tracking tool developed by Atlassian. It is widely used to manage Agile Scrum projects, track user stories, bugs, tasks, and project progress.

**Uses of Jira:**
- Create User Stories
- Track Bugs
- Sprint Planning
- Backlog Management
- Project Reporting

---

## What is an Epic?

An **Epic** is a large feature or requirement that cannot be completed in a single Sprint. It is divided into multiple User Stories.

**Example:**

Epic: User Authentication

---

## What is a User Story?

A **User Story** is the smallest unit of work in Agile. It describes a feature from the user's perspective and explains the value it provides.

**Example:**

As a customer,

I want to log in,

So that I can access my account.

---

## Difference between Epic and User Story

| Epic | User Story |
|------|------------|
| Large feature | Small feature |
| Contains multiple User Stories | Individual requirement |
| Cannot be completed in one Sprint | Usually completed in one Sprint |
| High-level requirement | Detailed requirement |

---

## What is a Component?

A **Component** is a logical module or part of the application.

**Examples:**
- Login
- Dashboard
- Payment
- Profile

Components help organize work within a project.

---

## What is a Release Version?

A **Release Version** identifies the version of the application in which features or fixes will be delivered.

**Example:**
- Version 1.0
- Version 2.0
- Release 2026.1

---

## User Story Format

A standard User Story is written as:

**As a** <User>

**I want** <Feature>

**So that** <Benefit>

**Example:**

As a customer,

I want to reset my password,

So that I can recover my account.

---

## Backlog Refinement (Grooming)

Backlog Refinement is a meeting where the team prepares User Stories before Sprint Planning.

**Activities:**
- Review User Stories
- Define Acceptance Criteria
- Create Subtasks
- Estimate Story Complexity
- Clarify Requirements

---

## Acceptance Criteria

Acceptance Criteria are the conditions that must be satisfied before a User Story is considered complete.

**Example:**

User Story:
Login to the application.

Acceptance Criteria:
- Valid username and password should log in successfully.
- Invalid credentials should display an error message.
- Password should be hidden.
- Forgot Password link should be available.
